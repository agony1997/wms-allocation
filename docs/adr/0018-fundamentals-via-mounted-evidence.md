# 0018. 補強網路協議與執行期原理，證物採掛載式

日期：2026-08-12

## 狀態

已接受 (Accepted)

## 背景

技術學習清單天然偏向「**要裝起來的工具**」——Docker、Redis、k8s、CI 之類，因為它們有明確的引入動作，容易被列出來、也容易被檢查有沒有做。

這種偏向會漏掉一整類能力：**HTTP、TCP、交易隔離級別、AOP proxy 行為、JVM 觀測、Web 安全**。它們不需要引入任何東西，因為已經在系統裡運作了——REST API 就是 HTTP、悲觀鎖就活在某個隔離級別下、`AllocationService.executeAllocation` 就是一個 self-invocation 案例。既然沒有「要不要裝」的問題，它們就不會出現在任何技術清單上。

三個具體後果：

1. 台灣後端市場（傳產／金融／SI 為主的 Java 職缺）的面試考點正集中在這一類，而本專案雖然實作上大量用到，卻沒有留下可指認的證物或現成答案。
2. [ADR-0010](0010-custom-jwt-auth-without-spring-security.md)（手刻 JWT，不用 Spring Security）是顯眼的反常規決策，必被追問安全性，但該 ADR 只寫了「為什麼不用」，沒寫「風險怎麼補」——目前是**有問題、沒答案**的狀態。
3. [ADR-0006](0006-sequence-single-pessimistic-lock.md) 與 [ADR-0013](0013-inventory-pessimistic-lock.md) 兩篇鎖的決策，**都沒寫明所依賴的交易隔離級別**，等於鎖的正確性前提未載明。

## 決策

### 一、技術引入採證物制

任何技術要進入本專案，必須繳交兩樣東西，缺一即視為無需求的技術堆疊（面試中反成扣分——被問「這裡為什麼需要 Redis」答不出真實理由即露餡）：

1. **證物**：repo 內看得到的檔案、數據或文件——「我用過」不算證物
2. **必答題**：面試會被問的那一句，而且有答案

引入動機分兩種，**都正當，但要誠實標註**：**需求驅動**（專案出現該技術才能解決的真實問題）／**證物驅動**（職涯需要可展示的證據，功能上非必要）。走證物驅動的，ADR 必須寫明「學習動機大於功能需求」。

### 二、基礎能力採掛載式

上述能力不引入新技術，證物形態改為**指著既有實作講清楚**（說明文件、併發實驗紀錄、反例測試）。作為成本控制手段，它們**一律綁在既有工作上、不新增階段**——本專案的瓶頸是可用工時而非工作量，不能把一份知識缺口變成一個新工期區塊。

| # | 項目 | 掛在哪（已存在） | 證物 | 必答題 |
|---|------|-----------------|------|--------|
| A1 | **HTTP 全鏈路** | 登入流程、前端 dev proxy、[ADR-0003](0003-restful-response-without-envelope.md) | 一篇「一次登入請求的生命週期」：`curl -v` 實錄、status code 選擇依據、CORS preflight、keep-alive | 「為什麼回 409 不是 400？preflight 什麼時候會發？」 |
| A2 | **TCP 與連線池** | 階段 4 壓測、HikariCP、k8s TCP probe | 連線數觀測＋連線池大小 before/after | 「TIME_WAIT 為什麼堆積？池大小怎麼定？」 |
| A3 | **交易隔離級別** | [ADR-0006](0006-sequence-single-pessimistic-lock.md)／[ADR-0013](0013-inventory-pessimistic-lock.md) | 兩 session 併發實驗：髒讀／不可重複讀／幻讀在本專案設定下會不會發生，**結論寫回那兩篇 ADR** | 「你的悲觀鎖在哪個隔離級別下才成立？拿掉鎖會怎樣？」 |
| A4 | **AOP proxy 與 `@Transactional` 失效** | `AllocationService.executeAllocation` 的 self-invocation（該處**正確**，仍在同一交易邊界內） | 反例測試：proxy 被繞過導致交易不生效 | 「`@Transactional` 什麼時候會失效？」 |
| A5 | **JVM 觀測** | 階段 4 壓測 | GC log／jstack／heap 用量，併入效能報告 | 「瓶頸在 GC 還是 DB，怎麼判斷？」 |
| A6 | **Web 安全自評** | [ADR-0010](0010-custom-jwt-auth-without-spring-security.md) | 「手刻 JWT 的已知風險與對策」：token 存放（localStorage 的 XSS 面 vs cookie 的 CSRF 面）、簽章演算法、過期與更新、密鑰輪替；並列 SQL injection（JPA 參數化已防）與 CSRF（走 header 天然免疫）的現況 | 「為什麼不用 Spring Security？安全性誰保證？」 |
| A7 | **索引與執行計畫** | 階段 4 效能優化 | 執行計畫 before/after（index seek vs table scan） | 「怎麼確認索引真的被用到？」 |

**A6 是目前最大的裸露面**（見背景 §2），優先度高於其他項。

### 三、TCP Socket：FDO 加開通道

| 閘門 | 掛載點 | 證物 | 必答題 |
|------|--------|------|--------|
| 證物驅動（學習動機為主） | mock 工廠出貨（FDO）目前走 REST，**加開**一條 TCP 通道，不取代既有端點 | JDK `ServerSocket` ＋ thread pool、封包格式定義（長度前綴）、心跳與斷線重連、對應測試 | 「這段為什麼用 socket 不用 HTTP？黏包／半包怎麼處理？」 |

選這個掛載點的理由：TCP 長連線對接是台灣傳產、金融、物流最真實的 B2B 形態，而工廠出貨正是本專案唯一的外部系統邊界。**刻意不引入 Netty**——要練的是 socket 語意（封包切分、連線生命週期），Netty 會把它包掉，且為一個 mock 接口加一個網路框架就是本 ADR §一要擋的堆技術。

### 四、雲端經驗併入 Linux 手動部署

階段 5 的「不靠容器的手動部署＋runbook」本來就需要一台機器，改為**做在雲端 VM（IaaS）上**：增量成本僅機器月費，同時取得 Linux runbook 與雲端實務。**不另學託管服務**（EKS/RDS 等）——費用與時間都會失控，且與自建 k8s manifest 的敘事重複。

### 五、否決 MQ（Kafka／RabbitMQ）

本專案範疇（[ADR-0017](0017-scope-boundary-three-stage-mainline.md)）內沒有跨服務解耦需求：唯一的非同步工作是每日庫存快照，階段 5 已規劃抽成獨立排程服務，量級與失敗容忍度都不需要 broker。加 MQ 沒有真實需求，正是 §一要擋的堆技術。

**誠實承認代價**：台灣中大型電商／金融職缺常列 Kafka，這是明確的關鍵字損失。應對方式是把它變成一個能講的判斷——「這個系統為什麼不需要 MQ」，與「為什麼不拆微服務」同一類答案。

## 後果

- **正面**：面試考點密度最高的一批基礎能力被納入，且成本形態是文件工而非新工期區塊；A3 與 A6 同時補上兩個既有 ADR 的實質缺口；A4 把一個既有實作細節升級成可講的案例。
- **負面／承擔**：
  - §三的 socket 是純證物項目，功能上非必要，面試中必須主動承認學習動機。
  - socket 的封包切分、心跳、斷線重連除錯屬於環境／協議試錯，AI 幫不上多少忙，實際耗時可能高於預期。
  - 放棄 MQ 關鍵字（見§五）。
- **被否決的替代方案**：
  - **WebSocket 即時推播**：與 §三 socket 敘事重疊（同為長連線），卻要動前端，而前端投資已壓到最小。
  - **獨立的 socket 練習程式（不進本專案）**：成本較低，但證物與作品集脫鉤，講不進同一條敘事。
  - **雲端託管服務（EKS/RDS）**：費用與時間失控，與自建 k8s 重複。
  - **補 Oracle**：台灣傳產／金融佔比高，但另學一套 DB 的效益不及知道分頁／序列語法差異。
  - **把演算法題（LeetCode）排進階段表**：那是專案外的面試準備，混進工程階段會污染範疇。
