送貨單規格書 (SDO)
===
> 主要操作者：業務員
---

## 概述

業務員送貨給客戶的單據，記錄實際銷售、退貨、換貨、毀損。
系統於業務員「當日首次」領貨完成後，根據當日 PENDING 的 CPO（客戶預訂單）自動產生 SDO。

---

## 作業流程

```
┌─────────────────────────────────────────────────────────────────────────┐
│  階段 1: 系統產生 SDO                                                    │
│  ───────────────────                                                    │
│  - 業務員「首次」領貨完成 (SRO.status = RECEIVED)                        │
│  - 系統根據當日 PENDING 的 CPO 各自動產生一張 SDO                        │
│  - 預帶 CPO 的預訂品項                                                   │
│  - SDO.status = PENDING                                                 │
└─────────────────────────────────────────────────────────────────────────┘
        │
        ▼ 業務員出發送貨
┌─────────────────────────────────────────────────────────────────────────┐
│  階段 2: 送達客戶                                                        │
│  ─────────────                                                          │
│  - 業務員抵達客戶處                                                      │
│  - 確認送達，SDO.status = DELIVERED                                      │
│  - 記錄送達時間                                                          │
└─────────────────────────────────────────────────────────────────────────┘
        │
        ▼ 現場作業
┌─────────────────────────────────────────────────────────────────────────┐
│  階段 3: 交易處理                                                        │
│  ─────────────                                                          │
│  - 銷售：預訂品項 + 現場加購                                              │
│  - 退貨：客戶退回商品                                                    │
│  - 毀損：送貨過程中損壞                                                  │
│  - 調整 SDOD 明細                                                        │
└─────────────────────────────────────────────────────────────────────────┘
        │
        ▼ 客戶簽收
┌─────────────────────────────────────────────────────────────────────────┐
│  階段 4: 簽收完成                                                        │
│  ─────────────                                                          │
│  - 客戶確認簽收                                                          │
│  - SDO.status = SIGNED                                                  │
│  - 更新 CPO.status = COMPLETED                                          │
│  - 更新業務員儲位庫存                                                    │
└─────────────────────────────────────────────────────────────────────────┘
```

## 資料結構

> **本領域暫緩實作，以下 Entity 尚未建立**（範疇見 [ADR-0017](../../../adr/0017-scope-boundary-three-stage-mainline.md)）；實作時欄位定義以 Entity 為準，個別欄位語意見其 Javadoc：
> - 單頭：`src/main/java/com/agony/wmsallocation/entity/delivery/SalesDeliveryOrder.java`
> - 明細：`src/main/java/com/agony/wmsallocation/entity/delivery/SalesDeliveryOrderDetail.java`

結構重點（不隨欄位改名變動的部分）：

- SDO 由 SRO 「當日首次」領貨完成後系統自動產生，關聯客戶與業務員儲位（後續補領貨不再觸發自動開單，2026-07-21 定案）
- SDOD 類型：SALES（銷售）/ RETURN（退回良品）/ RETURN_STALE（退回呆品）/ EXCHANGE（換貨）/ DAMAGE（毀損）
- SDOD 的 `preOrderNo` 來自 CPO；現場加購時為 null

---

## SDO 狀態說明

| 狀態 | 說明 |
|------|------|
| PENDING | 待送貨（已產生，尚未出發） |
| DELIVERED | 已送達（抵達客戶處） |
| SIGNED | 已簽收（客戶確認完成） |

> **設計確認（2026-07-21）**：業務員負責固定通路配送，實務為強制送達，不存在「整單拒收／送不到」的情境，故上述三個狀態已完整涵蓋實際流程，刻意不設失敗／取消終態。

---

## SDOD 類型說明

| 類型 | 說明 | 庫存影響 |
|------|------|----------|
| SALES | 銷售 | 業務員儲位 -qty |
| RETURN | 退回良品 | 業務員儲位 +qty |
| RETURN_STALE | 退回呆品 | 進入報廢路線 (大庫 returnQty -> 銷毀) |
| EXCHANGE | 巡架換貨 | 同時收回與給出同等數量良品 (中性) |
| DAMAGE | 毀損 | 業務員儲位 -qty |

> **設計確認（2026-07-21）**：新增 `RETURN_STALE` 與 `EXCHANGE` 以支援送貨現場的良呆分流與換貨行為。

## 單據關係

```
SRO (領貨完成)
    │
    ▼ 系統自動產生
SDO ─┬─ SDOD (SALES, 來自 CPO 預訂)
     ├─ SDOD (SALES, 現場加購)
     ├─ SDOD (RETURN, 客戶退貨)
     └─ SDOD (DAMAGE, 毀損)
    │
    ▼ 簽收完成
(流程結束，不產生應收帳款紀錄——應收帳款已決議不實作)
```

## 現場加購處理

業務員車上有多餘商品時，可現場加購：

1. 新增 SDOD (type = SALES, preOrderNo = null)
2. 選擇批次（從業務員儲位庫存）
3. 輸入數量、單價
4. 簽收時一併計入

---

## 臨時補貨處理

客戶臨時要更多，業務員車上不夠：

1. 業務員回營業所
2. 產生新的 SRO（補領貨）
3. 回到客戶處，新增 SDOD

---

## API 設計

> 端點定義（路徑、HTTP method、請求/回應格式）以 Controller 為準，或由 Swagger/OpenAPI 自動產生。

對外提供的能力（操作者：業務員）：

- 查詢送貨單清單（含今日清單）
- 查詢單一送貨單
- 確認送達
- 客戶簽收
- 新增／更新明細（加購／退貨／毀損）

---

## 庫存影響

### 簽收完成後

| 類型 | 業務員儲位庫存 |
|------|----------------|
| SALES | 減少 |
| RETURN | 增加（需後續處理） |
| DAMAGE | 減少（記錄損失） |
